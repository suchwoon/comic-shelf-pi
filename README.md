# Shelf

PDF를 올려두고 읽던 곳에서 다시 펼치는 개인용 만화책장입니다. 영어 UI와 미니멀한 흑백 테마, PC·모바일 반응형 화면을 제공합니다. 책 제목과 파일 이름은 원래 언어를 유지합니다.

- 여러 PDF 순차 업로드, 큰 파일 분할 전송, 진행률과 처리 결과, 중복 파일 감지
- 첫 페이지 표지, 제목 검색·수정, 최근 읽은 순·제목순 정렬, 삭제
- 화면에 맞는 한 페이지·두 페이지 뷰어, 휠·키보드 페이지 이동, 좌우 읽기 방향, 전체 화면
- 서재·로그인·초대·계정 화면의 라이트/다크 테마, 버튼 하나로 전환
- 모바일에서는 좌우 화면 터치로 페이지 이동, 가운데 터치로 조작 UI 표시·숨기기
- 읽는 동안 다음 두 페이지와 이전 페이지를 미리 준비해 빠르게 전환
- 계정별로 서버에 읽던 페이지·방향 저장
- 로그인한 회원들이 함께 사용하는 공용 텍스트 채팅, 최근 대화 50개 표시
- 초대받은 회원만 가입, 관리자만 원본 PDF 다운로드·업로드·제목 수정·삭제
- 서버에서 만든 페이지 이미지로 열람, 로그인으로 보호된 페이지·표지 요청
- 원본 영구 저장, SQLite 메타데이터, HTTP Range 전송

## 실행

Node.js **24 LTS**가 필요합니다. `node:sqlite`와 서버 표지·페이지 생성용 네이티브 Canvas를 사용합니다.

```bash
cd comic-shelf
npm ci
node scripts/setup.mjs
npm run dev
```

서버와 같은 컴퓨터의 브라우저에서 <http://127.0.0.1:3000>을 엽니다. 최초 관리자 아이디는 `.env.local`의 `ADMIN_USERNAME`(기본 `admin`), 초기 비밀번호는 `BOOKS_PASSWORD`입니다. 계정이 처음 만들어진 뒤에는 화면의 **Account settings**에서 비밀번호를 변경합니다. 환경 변수는 기존 계정의 비밀번호를 덮어쓰지 않습니다. 설정 스크립트는 비밀번호가 없을 때만 새 비밀번호를 생성하며, 기존 비밀번호는 유지합니다. 기본 명령은 로컬 인터페이스에만 바인딩합니다. VS Code로 다른 컴퓨터에 SSH 접속했다면 아래 포트 전달을 사용하세요.

프로덕션 모드:

```bash
npm run build
npm start
```

## VS Code에서 라즈베리 파이에 원격 접속한 경우

앱은 파이에서 실행됩니다. PC 브라우저의 `127.0.0.1`은 PC 자신을 가리키므로, 파이의 3000번 포트를 SSH로 전달해야 합니다.

1. VS Code 하단의 **포트** 탭을 엽니다.
2. **포트 전달**에서 `3000`을 입력합니다. 이미 3000번 행이 있으면 이 단계는 생략합니다.
3. 해당 행의 **브라우저에서 열기** 아이콘으로 접속합니다.

PC의 3000번 포트가 사용 중이면 다른 번호로 연결될 수 있으므로 **포트 탭에 표시되는 전달된 주소**를 사용하세요. `dev` 폴더를 워크스페이스로 연 경우 상위 `.vscode/settings.json`이 3000번 포트의 자동 전달과 미리보기를 설정합니다. SSH 연결이 유지되는 동안 사용할 수 있습니다.

이 방법은 앱의 기본 로컬 바인딩으로 동작하며 SSH 접속 권한을 이용합니다. [VS Code 공식 포트 전달 안내](https://code.visualstudio.com/docs/remote/ssh#_forwarding-a-port-creating-ssh-tunnel)

## 설정

`.env.local`에서 설정합니다. 설정을 바꾼 뒤 서버를 재시작하세요.

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `BOOKS_PASSWORD` | 비어 있음 | 계정 DB가 비어 있을 때 최초 관리자를 만드는 초기 비밀번호. 기존 계정에는 적용되지 않습니다. |
| `ADMIN_USERNAME` | `admin` | 최초 관리자 아이디. 가입 초대로 생성한 회원은 읽기 전용입니다. |
| `PUBLIC_ORIGIN` | 비어 있음 | 도메인 연결 시 공개 주소. 예: `https://books.catfish.cc`. 경로 없이 입력합니다. |
| `DATA_DIR` | `./data` | PDF, 표지, 계정·세션·회원별 읽던 위치를 보관하는 영구 디렉터리 |
| `MAX_UPLOAD_MB` | `256` | 파일당 업로드 제한, MiB 단위. 최대 2048MiB |

책 목록은 회원들이 함께 이용하지만 읽던 페이지·방향은 계정별로 따로 저장됩니다. 같은 계정으로 로그인한 기기끼리는 읽던 위치를 공유합니다. 같은 읽기 세션에서 늦게 도착한 이전 저장은 무시하고, 같은 계정의 여러 기기에서 동시에 같은 책을 읽으면 나중에 저장한 위치가 반영됩니다.

서재 우측 하단의 **Chat**에서 회원들과 대화할 수 있습니다. 공용 방 하나에 사용자 이름과 전송 시간을 표시하며, PC에서는 작은 패널, 모바일에서는 전체 화면으로 열립니다. 메시지는 SQLite에 보관하고 최근 50개를 보여줍니다. 채팅창이 열려 있고 브라우저 탭이 보일 때만 약 3초마다 대화를 갱신합니다. 메시지는 최대 1,000자이며 Enter로 전송하고 Shift+Enter로 줄을 바꿉니다. 읽기 화면에서는 채팅창을 표시하지 않습니다.

헤더의 달·해 아이콘 버튼을 누르면 라이트/다크 모드가 바로 전환됩니다. 달은 다크 모드로, 해는 라이트 모드로 바꾸는 동작을 나타냅니다. System 선택지는 없으며, 저장된 선택이 없거나 이전에 System을 선택했다면 운영체제의 색상 설정을 초기값으로 사용합니다. 화면을 연 뒤 운영체제 설정이 바뀌어도 테마는 그대로 유지됩니다. 직접 선택한 모드는 해당 브라우저에 저장되어 새로고침·로그인 후에도 유지되며 같은 브라우저의 다른 탭에도 반영됩니다. 만화 뷰어는 다크 배경을 사용하며 PDF와 표지의 원본 색상은 유지합니다.

## 회원 초대와 권한

관리자는 **Account settings → Manage members → Create invitation**에서 초대 링크를 발급합니다. 링크를 지인에게 직접 전달하면 지인이 아이디와 비밀번호를 정해 가입합니다. 링크는 한 번만 사용할 수 있고 7일 후 만료됩니다. 누구나 가입하는 공개 회원 가입은 제공하지 않습니다.

| 기능 | 관리자 | 일반 회원 |
| --- | --- | --- |
| 책 열람, 개인 읽던 위치 저장 | 가능 | 가능 |
| 공용 채팅 읽기·메시지 전송 | 가능 | 가능 |
| 원본 PDF 다운로드 | 가능 | 불가 |
| PDF 업로드·제목 수정·삭제 | 가능 | 불가 |
| 회원 초대·차단·비밀번호 재설정 링크 발급 | 가능 | 불가 |
| 본인 비밀번호 변경 | 가능 | 가능 |

회원 차단은 기존 로그인도 즉시 해제합니다. 비밀번호 변경 시 다른 로그인 세션은 무효화됩니다. 비밀번호를 잊은 회원에게는 관리자가 일회용 재설정 링크를 전달할 수 있습니다. 새 비밀번호는 8~128자이며 비밀번호 원문은 DB에 저장하지 않습니다. [OWASP 비밀번호 보관 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)을 참고해 scrypt로 해시하고, 세션·초대 토큰도 해시만 보관합니다.

공용 비밀번호 버전에서 업데이트하면 기존 책은 그대로 유지되고 기존 읽던 위치는 최초 관리자에게 옮겨집니다. 기존 공용 로그인 쿠키는 사용할 수 없으므로 관리자 아이디로 다시 로그인합니다. 일반 회원의 읽던 위치는 처음부터 별도로 시작합니다.

관리자 비밀번호를 잊었다면 서버의 `.env.local`에 `BOOKS_PASSWORD`를 새 비밀번호로 설정한 뒤, 프로젝트 루트에서 로컬 복구 명령을 실행합니다. 책·회원은 유지하고 관리자 비밀번호와 세션만 재설정합니다.

```bash
node scripts/reset-admin-password.mjs
```

홈 네트워크에서 이용하려면 먼저 비밀번호를 설정하고 다음처럼 실행합니다.

```bash
npm run build
node node_modules/next/dist/bin/next start --hostname 0.0.0.0
```

도메인을 연결할 때는 `PUBLIC_ORIGIN`을 실제 HTTPS 주소로 설정합니다. 앱은 이 설정으로 요청 출처와 HTTPS 로그인 쿠키를 판단하며, 요청자가 바꿀 수 있는 `Host`를 인증 근거로 사용하지 않습니다. Cloudflare Tunnel을 같은 서버에서 실행하면 앱의 `127.0.0.1:3000` 바인딩을 유지할 수 있습니다. [도메인 연결과 자동 실행 안내](docs/deployment.md)를 참고하세요.

8MiB보다 큰 PDF는 8MiB 이하의 요청으로 나눠 전송하므로 Cloudflare Free의 요청당 100MB 제한 내에서 파일당 기본 256MiB까지 업로드할 수 있습니다. 파일 전체 크기는 `MAX_UPLOAD_MB`로 제한합니다. 큰 파일도 서버에서 스트리밍 처리하며 PDF 검증·중복 감지·표지 생성은 동일하게 수행합니다. 실패한 업로드는 처음부터 재시도하며, 사용하지 않는 임시 업로드는 만료 후 정리합니다. 분할 업로드 세션은 단일 Node.js 프로세스에서 관리하므로 같은 `DATA_DIR`를 여러 앱 프로세스가 공유하는 운영은 지원하지 않습니다. [Cloudflare 공식 업로드 제한](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/4xx-client-error/error-413/)

Docker 예시도 포함되어 있습니다. Docker Compose는 비밀번호 설정을 요구하며, 호스트의 127.0.0.1:3000에만 포트를 공개합니다.

```bash
# .env.local에 비밀번호를 먼저 설정
docker compose --env-file .env.local up --build -d
```

`books` 이름의 Docker 영구 볼륨에 자료를 보관합니다. 임시 파일 시스템이나 서버리스 인스턴스의 로컬 디스크를 영구 저장소로 사용하면 안 됩니다.

## 파일 보관과 백업

기본 데이터 디렉터리:

```text
data/
  books/          원본 PDF
  covers/         첫 페이지 표지
  pages/          열람용 페이지 이미지 캐시 (서버에서 다시 생성 가능)
  tmp/            업로드·검증 중 임시 파일
  library.sqlite  계정, 세션, 초대, 제목, 파일 정보, 회원별 읽던 위치
```

이전 버전의 `session-secret` 파일이 남아 있어도 새 계정 세션에는 사용하지 않습니다. SQLite는 실행 중 WAL 파일도 사용할 수 있습니다. **서버를 정상 종료한 뒤 데이터 디렉터리 전체를 백업**하는 방식이 가장 단순합니다.

```bash
# 서버를 종료한 후, 프로젝트 루트에서 실행
tar -czf comic-shelf-backup.tar.gz data
```

복원할 때는 서버를 종료하고 빈 데이터 위치에 압축을 풀어 `DATA_DIR`로 지정합니다. 파일 권한과 실행 사용자를 맞춘 뒤 서버를 실행하세요. 삭제는 원본 PDF·표지·페이지 이미지 캐시·읽던 위치를 함께 제거하며, 휴지통 기능은 없습니다. Docker에서는 서버 컨테이너를 중지한 뒤 `books` 볼륨 전체를 별도로 백업하세요. `docker compose down -v`는 영구 볼륨까지 삭제합니다.

## Git 관리

`comic-shelf/`를 루트로 하는 독립 Git 저장소로 관리합니다. 소스 코드, 테스트, 설정 파일, `package-lock.json`, `.env.example`을 기록합니다. 개인 PDF·표지·SQLite 등이 담긴 `data/`, 환경 설정 `.env`·`.env.*` (`.env.example` 제외), `.cloudflared/`의 터널 자격 증명, `.runtime/`의 실행 도구, `comic-shelf-backup*.tar.gz` 백업, 의존성·빌드 결과·로그는 `.gitignore`로 제외합니다. 개인 데이터와 백업은 별도로 보관하세요.

프로젝트 루트에서 변경 사항을 확인하고 커밋합니다.

```bash
git status
git diff
git add .
git diff --cached
git commit -m "변경 내용 요약"
```

## 첫 버전의 범위

모바일·터치 기기에서는 책을 열면 조작 UI가 숨겨집니다. 화면의 왼쪽 1/3은 이전 페이지, 오른쪽 1/3은 다음 페이지, 가운데 1/3은 UI 표시·숨기기입니다. 오른쪽부터 읽기 모드에서는 좌우 이동이 반대가 됩니다. UI는 페이지 위에 겹쳐 표시되므로 여닫아도 페이지 크기는 유지됩니다. 가로 화면에서도 같은 방식으로 조작하며, 드래그·길게 누르기·여러 손가락 조작으로는 페이지가 넘어가지 않습니다. 브라우저로 확대해 보는 동안에도 페이지 이동은 잠시 멈추고 가운데 터치로 UI를 열 수 있습니다. PC에서는 기존 버튼과 키보드 조작을 사용합니다.

페이지 영역에서 휠을 내리면 다음 페이지, 올리면 이전 페이지로 이동하며 오른쪽부터 읽기에서도 같은 규칙을 사용합니다. 터치패드의 연속 입력은 한 동작으로 묶고, 확대·스크롤 중에는 페이지 이동을 멈춥니다. 읽기 방향 버튼은 현재 진행 방향을 오른쪽 또는 왼쪽 화살표로 표시합니다.

상단의 **Two-page view** 버튼으로 두 페이지 보기를 선택할 수 있으며 선택은 현재 브라우저에 저장됩니다. 표지는 단독으로, 이후 2–3, 4–5처럼 표시하고 오른쪽부터 읽기에서는 좌우 배치를 뒤집습니다. 묶음에 가로 페이지가 있으면 해당 두 페이지를 각각 단독 표시하며 다음 묶음의 시작 위치는 유지합니다. 이동 버튼·키보드·휠·터치는 한 묶음씩 이동하고 보기 방식을 바꿔도 읽던 페이지는 유지합니다. 페이지 번호에는 표시 중인 범위가 나오며 누르면 원하는 페이지 번호를 입력할 수 있습니다.

암호가 필요한 PDF, OCR, 연속 스크롤, 오프라인 읽기와 업로드 중단 지점부터 이어 보내기는 지원하지 않습니다. 실패한 업로드는 처음부터 재시도합니다. 서버는 업로드 후 PDF 확인과 작은 표지 생성을 별도 프로세스에서 제한 시간 내 처리합니다. 파일 크기가 제한 이내라도 손상되었거나 처리하기 지나치게 복잡한 PDF는 오류로 안내될 수 있습니다.

뷰어는 현재 페이지를 포함해 최대 네 장의 완성된 화면을 재사용합니다. 렌더링 중인 화면까지 합쳐 캔버스 픽셀을 1,600만 개(약 64MB)로 제한하므로, 화면 크기에 따라 미리 준비하는 장수는 줄어들 수 있습니다. 이 한도는 이미지 디코딩·브라우저 전체 메모리와는 별개입니다. 창 크기가 바뀌거나 PC에서 조작 버튼 표시 여부가 달라지면 화면에 맞춰 다시 준비하며, 새 페이지가 준비되는 동안 기존 화면을 유지하고 200ms 이상 걸릴 때만 전환 로딩을 표시합니다. 이전 버전에서 저장한 너비 맞춤 설정도 책을 열면 페이지 전체 맞춤으로 바뀝니다.

PDF.js와 네이티브 Canvas는 서버에서 표지와 열람용 JPEG 페이지 이미지를 생성합니다. 뷰어는 관리자·일반 회원 모두 페이지 이미지만 받아 표시하며 원본 PDF를 받지 않습니다. 원본 PDF API는 GET·HEAD·Range 요청 모두 관리자 권한을 검사하고, 서재의 다운로드 버튼도 관리자에게만 표시합니다. 페이지 이미지와 원본 PDF는 `private, no-store`로 응답하며, 서버의 이미지 캐시는 공개 정적 경로 밖에 보관합니다. 페이지 이미지는 처음 열 때 생성하며 긴 변을 최대 2,400px로 제한합니다. 동시에 두 페이지까지 생성하고 각 작업은 30초 안에 끝나야 합니다. 디스크 캐시는 최대 192MiB를 유지하도록 오래 사용하지 않은 이미지부터 제거하며 필요할 때 다시 생성합니다.

이 제한은 **원본 PDF 접근 차단**입니다. 사용자가 볼 수 있는 화면을 캡처하거나 페이지 이미지를 모아 새 PDF를 만드는 것까지 웹에서 완전히 막을 수는 없으며, 이전에 내려받은 파일도 회수할 수 없습니다. 외부 PDF 뷰어 서비스나 폰트 CDN을 사용하지 않습니다. Cloudflare Tunnel로 연결한 도메인에서는 페이지 이미지와 관리자 PDF 다운로드 요청이 Cloudflare를 거쳐 서버로 전달됩니다. 의존성은 `package-lock.json`으로 고정합니다.
